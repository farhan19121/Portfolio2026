# AI Development Instructions

## Before Making Changes
1. Read all files inside `/docs`.
2. Understand the existing codebase before editing.
3. Follow `PORTFOLIO_CONTENT.md` as the source of truth.
4. Do not invent personal information or achievements.

## Development Rules
- Use reusable components
- Keep components modular
- Avoid unnecessary dependencies
- Use semantic HTML
- Prioritize accessibility
- Maintain responsive design
- Prefer simple solutions

## Design Rules
- Follow `DESIGN_SYSTEM.md`
- Keep spacing consistent
- Keep animations subtle
- Avoid generic portfolio patterns
- Prioritize readability

## Content Rules
Never invent:
- Metrics
- Company names
- Job titles
- Certifications
- Project findings
- Awards
- URLs

If information is missing, use a clear placeholder or ask the user.

## Change Management
Before major changes:
1. Explain the implementation plan.
2. Identify affected components.
3. Avoid rewriting unrelated code.

After changes:
1. Check for build errors.
2. Check desktop responsiveness.
3. Check mobile responsiveness.
4. Verify navigation and interactions.
5. Check for layout overflow.

## Preferred Workflow
Plan → Implement → Test → Review → Refine

Do not make large uncontrolled changes across the entire project unless explicitly requested.
